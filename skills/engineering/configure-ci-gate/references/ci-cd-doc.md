# CI/CD document template

Read when generating `docs/ci-cd.md`. Placeholders are `<<name>>`, filled by the same rules as the GitHub CI templates.

- `<<default_branch>>` and `<<ci_command>>`: `default_branch` and `ci.command` from the marker.
- `<<check_rows>>`: one row per `ci.checks` item in marker order: `| <name> | \`<run>\` | yes |` for `required: true`, and `| <name> | \`<run>\` | no, advisory |` for `required: false`.
- Use the section for the marker's `forge`, and its gap list verbatim.
- Forgejo only: `<<signed_rule>>` is `Signed commits required; the instance signs merge commits.` when the instance publishes a signing key, otherwise nothing. `<<signed_gap>>` is `Signed commits are not required: this instance has no signing key, and requiring them would block every merge.` when it does not, otherwise nothing.

## GitHub

````markdown
# CI/CD

Generated by `configure-ci-gate` from `.claude/64x-lunicorn.yml`. Change the checks there and re-run setup; edits made here are reported as drift.

## The gate

Every pull request into `<<default_branch>>` runs these checks. The only required status check is `CI gate`: it runs after all of them and is green only when every blocking one succeeded.

| Check | Command | Blocks the merge |
| :--- | :--- | :--- |
<<check_rows>>
| Workflow lint | actionlint on `.github/workflows`, zizmor on `.github` | yes |
| Secret scan | gitleaks over the full history | yes |

## Run it locally

```bash
<<ci_command>>
```

## Rules on `<<default_branch>>`

- Pull request required, squash merge only, head branch deleted after merge.
- Signed commits, linear history, no force push, no deletion.
- `CI gate` required, reported by GitHub Actions.
- 0 approvals and no bypass: the pull request is mandatory so the gate runs.

## Keeping it current

Dependabot opens weekly pull requests for dependencies and for the SHA-pinned actions. A change to the checks goes into `.claude/64x-lunicorn.yml`, followed by a setup re-run.

## Gaps

None on GitHub.
````

````markdown
# CI/CD

Generated by `configure-ci-gate` from `.claude/64x-lunicorn.yml`. Change the checks there and re-run setup; edits made here are reported as drift.

## The gate

Every merge request into `<<default_branch>>` runs a pipeline with these jobs. The project setting "Pipelines must succeed" blocks the merge until the pipeline succeeded; its last job, `CI gate`, runs only when every blocking job did.

| Check | Command | Blocks the merge |
| :--- | :--- | :--- |
<<check_rows>>
| Secret scan | gitleaks over the full history | yes |

GitLab validates `.gitlab-ci.yml` when it creates the pipeline, so an invalid file fails the merge request.

## Run it locally

```bash
<<ci_command>>
```

## Rules on `<<default_branch>>`

- Protected: nobody pushes directly, maintainers merge, no force push.
- Squash always, fast-forward merge for a linear history, source branch deleted after merge.
- "Pipelines must succeed" is on, and a skipped pipeline does not count as success.
- 0 approvals: the merge request is mandatory so the pipeline runs.

## Keeping it current

`renovate.json` configures Renovate for dependencies and CI images, weekly, with a seven-day minimum release age. A change to the checks goes into `.claude/64x-lunicorn.yml`, followed by a setup re-run.

## Gaps

- Signed commits cannot be enforced: the push rule "Reject unsigned commits" needs GitLab Premium.
- Squash commits GitLab creates are signed only when the instance configures commit signing.
- No workflow lint beyond GitLab's own validation: actionlint and zizmor cover GitHub Actions only, and the job token cannot call the lint API.
- The job token cannot be narrowed per job.
- Renovate acts only once a Renovate bot is installed for the project.
````

````markdown
## Rules on `<<default_branch>>`

- Pushes disabled: every change arrives through a pull request.
- Squash merge only, head branch deleted after merge by default.
- `CI / CI gate (pull_request)` required, and the branch must be up to date with `<<default_branch>>`.
- <<signed_rule>>

`renovate.json` configures Renovate for dependencies and the SHA-pinned actions, weekly, with a seven-day minimum release age. A change to the checks goes into `.claude/64x-lunicorn.yml`, followed by a setup re-run.

- Forgejo Actions ignores job-level `permissions`, so the job token cannot be narrowed.
````

## No forge

````markdown
# CI/CD

Generated by `configure-ci-gate` from `.claude/64x-lunicorn.yml`. Change the checks there and re-run setup; edits made here are reported as drift.

## The gate

Without a forge, the gate runs as git hooks. It runs every check below through one command:

```bash
<<ci_command>>
```

| Check | Command | Blocks |
| :--- | :--- | :--- |
<<check_rows>>

## Rules on `<<default_branch>>`

- `pre-commit` rejects commits on `<<default_branch>>`. The only exception is the commit that finishes `git merge --squash`, and it must pass the gate.
- `pre-push` runs the gate before anything is pushed.

## After cloning

Activate the hooks once per clone:

```bash
git config core.hooksPath .githooks
```

## Gaps

- `git commit --no-verify` skips `pre-commit`; the rule holds by convention.
- Signed commits and linear history hold by convention.
- Workflow lint and Secret scan run only on a forge.
- Advisory checks cannot be told apart locally: `<<ci_command>>` has to succeed as a whole.
````
