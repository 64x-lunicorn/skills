# Forgejo CI templates

Read when generating `.forgejo/workflows/ci.yml`, `.forgejo/actionlint.yaml` and `renovate.json` for `forge: forgejo`. `${{ }}` is Forgejo Actions syntax and stays as it is. Verified 2026-09-14 against Forgejo 16.0.4 with Forgejo Runner 13.1.0.

## Fill rules

- A placeholder is replaced by its value alone. Quotes written around a placeholder stay; none are added. Inside double quotes, `\` and `"` in the value are escaped.
- A placeholder that resolves to nothing is removed together with its whole line.
- A generated file is the content of its fenced block below, ending with exactly one newline.
- `<<default_branch>>`: `default_branch` from the marker.
- `<<runner>>`: `ci.runner` from the marker.
- `<<setup_steps>>`: the stack's Forgejo setup steps from the runtime templates, inserted as they are.
- `<<required_entries>>`: one entry per `ci.checks` item with `required: true`, in marker order, in exactly this shape and indentation:

  ```yaml
            - name: "<name>"
              run: "<run>"
  ```

- `<<advisory_job>>`: nothing when no check has `required: false`. Otherwise the advisory job block below, with `<<advisory_entries>>` filled like `<<required_entries>>` from the checks with `required: false`.

## Why it looks like this

- **Advisory checks are a separate job.** Forgejo ignores `continue-on-error` on jobs, and on steps it accepts only a literal: `continue-on-error: ${{ matrix.required == false }}` makes the whole workflow invalid (`cannot unmarshal !!str into bool`). So advisory checks run in their own matrix job that `CI gate` does not wait for; a failure shows red and never blocks.
- **The required status is `CI / CI gate (pull_request)`.** Forgejo names commit statuses `<workflow name> / <job name> (<event>)`, and branch protection matches that exact string.
- **Actions in short form.** `actions/checkout@<sha>` resolves through the instance's default actions mirror and passes actionlint. The `https://github.com/...` form also runs, but actionlint rejects it.
- **No `permissions`.** Forgejo ignores job-level permissions, so the job token cannot be narrowed; the CI/CD document names it as a gap.
- **Tools by checksum, per architecture.** Forgejo runners exist for `x86_64` and `arm64`.

## `.forgejo/workflows/ci.yml`

````yaml
# The quality gate. It runs on every pull request into <<default_branch>> and
# ends in one job, "CI gate", whose status "CI / CI gate (pull_request)" is
# the only check the branch protection requires.
#
# Generated by configure-ci-gate from .claude/64x-lunicorn.yml. Change the
# checks there and re-run setup; edits made here are reported as drift.
#
# Design notes:
#   * Required checks run as one matrix. Advisory checks run as another that
#     the gate does not wait for, because Forgejo ignores continue-on-error on
#     jobs.
#   * Actions are pinned to a commit SHA and resolve through the instance's
#     actions mirror. Renovate keeps them current.
#   * Forgejo ignores job-level permissions; the job token cannot be narrowed.
name: CI

on:
  pull_request:
    branches: [<<default_branch>>]

# A superseded push to a pull request has nothing left to prove.
concurrency:
  group: ci-${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

jobs:
  checks:
    name: ${{ matrix.name }}
    runs-on: <<runner>>
    strategy:
      fail-fast: false
      matrix:
        include:
<<required_entries>>
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          # checkout otherwise leaves the workflow token in .git/config,
          # readable by every later step in the job.
          persist-credentials: false

<<setup_steps>>

      - name: Run check
        env:
          CHECK_RUN: ${{ matrix.run }}
        run: bash -c "${CHECK_RUN}"

<<advisory_job>>
  workflows:
    name: Workflow lint
    runs-on: <<runner>>
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false

      - name: actionlint
        env:
          ACTIONLINT_VERSION: 1.7.12
        run: |
          set -euo pipefail
          case "$(uname -m)" in
            x86_64) ACTIONLINT_ARCH=amd64; ACTIONLINT_SHA256=8aca8db96f1b94770f1b0d72b6dddcb1ebb8123cb3712530b08cc387b349a3d8 ;;
            aarch64 | arm64) ACTIONLINT_ARCH=arm64; ACTIONLINT_SHA256=325e971b6ba9bfa504672e29be93c24981eeb1c07576d730e9f7c8805afff0c6 ;;
            *) echo "Unsupported runner architecture: $(uname -m)" >&2; exit 1 ;;
          esac
          curl -sSfL -o actionlint.tar.gz \
            "https://github.com/rhysd/actionlint/releases/download/v${ACTIONLINT_VERSION}/actionlint_${ACTIONLINT_VERSION}_linux_${ACTIONLINT_ARCH}.tar.gz"
          echo "${ACTIONLINT_SHA256}  actionlint.tar.gz" | sha256sum -c -
          tar -xzf actionlint.tar.gz actionlint
          ./actionlint -color -config-file .forgejo/actionlint.yaml .forgejo/workflows/*.yml

  secrets:
    name: Secret scan
    runs-on: <<runner>>
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false
          # Full history: a credential committed and "removed" later is still
          # in the repository and still leaked.
          fetch-depth: 0

      - name: gitleaks
        env:
          GITLEAKS_VERSION: 8.30.1
        run: |
          set -euo pipefail
          case "$(uname -m)" in
            x86_64) GITLEAKS_ARCH=x64; GITLEAKS_SHA256=551f6fc83ea457d62a0d98237cbad105af8d557003051f41f3e7ca7b3f2470eb ;;
            aarch64 | arm64) GITLEAKS_ARCH=arm64; GITLEAKS_SHA256=e4a487ee7ccd7d3a7f7ec08657610aa3606637dab924210b3aee62570fb4b080 ;;
            *) echo "Unsupported runner architecture: $(uname -m)" >&2; exit 1 ;;
          esac
          curl -sSfL -o gitleaks.tar.gz \
            "https://github.com/gitleaks/gitleaks/releases/download/v${GITLEAKS_VERSION}/gitleaks_${GITLEAKS_VERSION}_linux_${GITLEAKS_ARCH}.tar.gz"
          echo "${GITLEAKS_SHA256}  gitleaks.tar.gz" | sha256sum -c -
          tar -xzf gitleaks.tar.gz gitleaks
          ./gitleaks git --no-banner --redact --exit-code 1 .

  # The one job the branch protection requires. A skipped or cancelled job
  # cannot pass as green, and advisory checks are not among the needs.
  gate:
    name: CI gate
    if: always()
    needs: [checks, workflows, secrets]
    runs-on: <<runner>>
    steps:
      - name: Verify every job succeeded
        env:
          RESULTS: ${{ join(needs.*.result, ' ') }}
        run: |
          set -euo pipefail
          echo "job results: ${RESULTS}"
          for result in ${RESULTS}; do
            if [ "${result}" != "success" ]; then
              echo "A required CI job did not succeed (${RESULTS})."
              exit 1
            fi
          done
          echo "All required CI jobs succeeded."
````

### Advisory job block

````yaml
  # Advisory checks. Their failure shows red and never blocks: CI gate does
  # not wait for this job.
  advisory:
    name: ${{ matrix.name }}
    runs-on: <<runner>>
    strategy:
      fail-fast: false
      matrix:
        include:
<<advisory_entries>>
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with:
          persist-credentials: false

<<setup_steps>>

      - name: Run check
        env:
          CHECK_RUN: ${{ matrix.run }}
        run: bash -c "${CHECK_RUN}"

````

```yaml
# Generated by configure-ci-gate. actionlint only knows GitHub's runner
# labels; this names the Forgejo runner label the workflows use.
self-hosted-runner:
  labels:
    - <<runner>>
```

## `renovate.json`

The same file as on GitLab. Renovate replaces Dependabot outside GitHub; it only acts once a Renovate bot is installed for the repository, which the CI/CD document names as a gap.

```json
{
  "$schema": "https://docs.renovatebot.com/renovate-schema.json",
  "extends": ["config:recommended"],
  "timezone": "Europe/Berlin",
  "schedule": ["* 6 * * 1"],
  "minimumReleaseAge": "7 days",
  "prConcurrentLimit": 5,
  "labels": ["dependencies"],
  "packageRules": [
    {
      "matchManagers": ["github-actions", "gitlabci"],
      "groupName": "CI"
    }
  ]
}
```
