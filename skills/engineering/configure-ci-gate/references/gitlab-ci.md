# GitLab CI templates

Read when generating `.gitlab-ci.yml` and `renovate.json` for `forge: gitlab`. Verified 2026-09-14 against GitLab CE 19.2.6 with a Docker runner.

## Fill rules

- A placeholder is replaced by its value alone. Inside double quotes, `\` and `"` in the value are escaped.
- A placeholder that resolves to nothing is removed together with its whole line.
- A generated file is the content of its fenced block below, ending with exactly one newline.
- `<<default_branch>>`: `default_branch` from the marker.
- `<<image>>` and `<<before_script>>`: the stack's GitLab entry in the runtime templates.
- `<<tags>>`: nothing when `ci.runner` is `[]`; otherwise `  tags:` followed by one line `    - "<tag>"` per tag, in marker order.
- `<<check_jobs>>`: one job per `ci.checks` item, in marker order, separated by one blank line, in exactly this shape. The `allow_failure` line exists only for `required: false`:

  ```yaml
  "<name>":
    stage: checks
    allow_failure: true
    script:
      - "<run>"
  ```

## Why it looks like this

- **The pipeline is the gate.** The project setting "Pipelines must succeed" blocks a merge request whose pipeline did not succeed. A job with `allow_failure: true` fails visibly and the pipeline still succeeds. The last stage holds `CI gate`, which only runs when every blocking job succeeded, so the house name exists on GitLab too.
- **No Workflow lint job.** GitLab validates `.gitlab-ci.yml` when it creates the pipeline; an invalid file gives a failed pipeline and a merge request that cannot be merged. A lint job could not call the lint API anyway: `CI_JOB_TOKEN` gets `404 Project Not Found` on `/projects/:id/ci/lint`, so it would need a stored personal or project token. The skill lints with the API in step 3 instead.
- **Tools by checksum, per architecture.** gitleaks is downloaded at a pinned version and verified, for `x86_64` and `arm64` runners.

## `.gitlab-ci.yml`

````yaml
# The quality gate. It runs on every merge request into <<default_branch>> and
# ends in one job, "CI gate". The project setting "Pipelines must succeed"
# makes this pipeline the only thing that can block a merge.
#
# Generated by configure-ci-gate from .claude/64x-lunicorn.yml. Change the
# checks there and re-run setup; edits made here are reported as drift.
#
# Design notes:
#   * One job per check from ci.checks. A check with required: false has
#     allow_failure: true: it shows its failure and never blocks.
#   * GitLab validates this file when it creates the pipeline, so an invalid
#     file fails the merge request instead of passing silently.
#   * Tools are downloaded at pinned versions and verified by checksum.
workflow:
  rules:
    - if: $CI_PIPELINE_SOURCE == "merge_request_event" && $CI_MERGE_REQUEST_TARGET_BRANCH_NAME == "<<default_branch>>"

stages:
  - checks
  - gate

default:
  image: <<image>>
  interruptible: true
<<tags>>
  before_script:
<<before_script>>

<<check_jobs>>

Secret scan:
  stage: checks
  image: buildpack-deps:bookworm-scm
  variables:
    # Full history: a credential committed and "removed" later is still in
    # the repository and still leaked.
    GIT_DEPTH: "0"
    GITLEAKS_VERSION: 8.30.1
  before_script: []
  script:
    - |
      set -euo pipefail
      case "$(uname -m)" in
        x86_64) GITLEAKS_ARCH=x64; GITLEAKS_SHA256=551f6fc83ea457d62a0d98237cbad105af8d557003051f41f3e7ca7b3f2470eb ;;
        aarch64 | arm64) GITLEAKS_ARCH=arm64; GITLEAKS_SHA256=e4a487ee7ccd7d3a7f7ec08657610aa3606637dab924210b3aee62570fb4b080 ;;
        *) echo "Unsupported runner architecture: $(uname -m)" >&2; exit 1 ;;
      esac
      curl -sSfL -o gitleaks.tar.gz "https://github.com/gitleaks/gitleaks/releases/download/v${GITLEAKS_VERSION}/gitleaks_${GITLEAKS_VERSION}_linux_${GITLEAKS_ARCH}.tar.gz"
      echo "${GITLEAKS_SHA256}  gitleaks.tar.gz" | sha256sum -c -
      tar -xzf gitleaks.tar.gz gitleaks
      ./gitleaks git --no-banner --redact --exit-code 1 .

# The job the house gate is named after. It runs only when every blocking job
# above succeeded; "Pipelines must succeed" does the blocking.
CI gate:
  stage: gate
  image: buildpack-deps:bookworm-scm
  before_script: []
  script:
    - echo "All blocking jobs succeeded."
````

## `renovate.json`

Shared with Forgejo. Renovate replaces Dependabot outside GitHub; it only acts once a Renovate bot is installed for the project, which the CI/CD document names as a gap.

```json
{
  "$schema": "https://docs.renovatebot.com/renovate-schema.json",
  "extends": ["config:recommended"],
  "timezone": "Europe/Berlin",
  "schedule": ["* 6 * * 1"],
  "minimumReleaseAge": "7 days",
  "prConcurrentLimit": 5,
  "labels": ["dependencies"],
  "packageRules": [
    {
      "matchManagers": ["github-actions", "gitlabci"],
      "groupName": "CI"
    }
  ]
}
```
