# No-forge templates

Read when the marker says `forge: none`. Both hooks live in `.githooks/`, belong in the repository, and are executable (`chmod +x`). `git config core.hooksPath .githooks` activates them for one clone; every new clone runs that command once, which `docs/ci-cd.md` states.

Placeholders: `<<default_branch>>` and `<<ci_command>>` from the marker, inserted verbatim. A hook file is the content of its fenced block, ending with exactly one newline.

Without a forge, changes reach the default branch through `git merge --squash` from a branch. The squash commit is itself a commit on the default branch, so `pre-commit` lets exactly that commit through, and runs the gate on it. The gate runs on the working tree, so the hook first refuses unstaged and untracked changes: otherwise files that are not part of the commit could make the gate pass.

## `.githooks/pre-commit`

```sh
#!/bin/sh
# Generated by configure-ci-gate. Commits on <<default_branch>> are rejected,
# except the commit that finishes a `git merge --squash`, which must pass the
# gate first. Work happens on branches.
set -eu

branch=$(git symbolic-ref --quiet --short HEAD) || exit 0
[ "$branch" = "<<default_branch>>" ] || exit 0

if [ -f "$(git rev-parse --git-path SQUASH_MSG)" ]; then
  if ! git diff --quiet || [ -n "$(git ls-files --others --exclude-standard)" ]; then
    echo "Unstaged or untracked changes would be tested with this commit. Stash them or move them to a branch first." >&2
    exit 1
  fi
  echo "Squash merge into <<default_branch>>: running the gate." >&2
  <<ci_command>>
  exit 0
fi

echo "Commits on <<default_branch>> are not allowed. Commit on a branch, then merge it with git merge --squash." >&2
exit 1
```

## `.githooks/pre-push`

```sh
#!/bin/sh
# Generated by configure-ci-gate. Nothing leaves this machine without passing
# the gate.
set -eu

echo "Running the gate before push." >&2
<<ci_command>>
```
